# Agent2 登录 Shell 环境快照设计

## 目标

Agent2 的后台命令在 macOS 和 Linux 图形化启动 ssterm 时，也能找到由用户登录
shell 配置加入的命令，例如 Homebrew、asdf、mise、pyenv 或 nvm 的可执行文件。它
仍然必须是每条命令一个受宿主控制的后台子进程，不能退化为向长期 PTY 注入文本。

## 范围与边界

- 仅作用于本机 macOS/Linux 的 Agent2 后台执行。
- SSH 继续由远端登录环境决定；Windows、WSL 和 Git Bash 继续使用既有专用启动与
  环境策略。
- 快照只保存经过校验的 `PATH`，不保存完整环境、密钥、别名、函数或用户命令输出。
- 快照是内存态的，按 shell 可执行路径缓存，不写入命令历史、应用日志或磁盘。

## 设计

新增 `LoginShellEnvironmentResolver`。首次需要某个受支持 POSIX shell 的 Agent2
环境时，它启动一次短生命周期的真实登录 shell：

```
<shell> -l -c 'printf "%s\\0" "$PATH"'
```

解析器以 NUL 作为唯一输出边界，设置严格的短超时与输出上限，并仅接受非空、无 NUL
字符的 PATH。成功后将 PATH 按 shell 可执行路径缓存。`BackgroundCommandExecutor`
在启动每条本地 POSIX 后台命令时，用该缓存 PATH 覆盖继承的应用 PATH；命令本身依旧以
`<shell> -c <command>` 单独启动。

若登录 shell 启动失败、超时、退出非零、输出不合法或用户配置写入额外输出，解析器不
阻断命令：返回空覆盖并使用现有应用环境。失败原因只作为本地诊断信息，不能包含 PATH
或 shell 输出。

缓存不会自动重新加载；用户重启应用或重新创建 Agent2 会话即可得到新的登录环境。后续
可在设置中增加显式刷新，但不在本次范围内。

## 生命周期与取消

环境解析属于开始后台命令前的初始化工作，和该命令共用取消代际。若该请求已被取消，
解析结果不得再启动命令。解析器结束后不会保留子进程；超时会终止并等待其退出。

## 测试

- 解析 NUL 终止 PATH，并验证同一个 shell 只执行一次解析。
- 空值、异常输出、非零退出、超时均安全回退，不改变原有环境。
- POSIX 后台执行使用解析后的 PATH；Windows/WSL 路径不调用解析器。
- 现有背景执行、取消、超时和命令历史测试必须继续通过。
