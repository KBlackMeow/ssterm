# Agent Auto 文件写入：会话级逐文件信任边界

**日期：** 2026-08-20  
**状态：** 待设计确认

## 问题

ssterm 的 Auto 模式目前只会自动执行已允许的终端命令。`write_file` 和
`edit_file` 始终展示 Apply / Reject 卡片，因此 Agent 即使只是在项目中创建
一个新文件也会暂停。

直接把所有工作目录内的编辑自动批准风险过高：Agent 可能覆盖用户原有文件、
生成配置或修改不属于当前任务的内容。

## 决策

Auto 模式启用且“文件写入”设置已启用时，引入**会话级逐文件信任清单**。

### 自动写入许可

`write_file` 可以不经 Apply 直接创建文件，当且仅当：

1. 路径经过 adapter 解析后，位于当前 Agent 工作目录之内，或位于 `/tmp`；
2. preview 确认目标在本次写入前不存在；
3. 文件写入功能仍启用，adapter 可用。

成功创建后，将解析后的精确路径以及提交返回的 mtime 记入当前 Agent 会话的
临时信任清单。

任意 `write_file` 覆盖或 `edit_file` 修改也可进入该清单：用户对该文件的提案
点击 Apply 并且提交成功后，记录其精确解析路径和最新 mtime。

### 已信任文件的后续修改

Auto 模式下，`write_file` 覆盖或 `edit_file` 修改某个已信任文件时无需 Apply，
但在提交前必须：

1. 再次 preview，重新确认解析路径仍在允许位置；
2. 确认目标仍存在，且其 mtime 与清单中 Agent 上次成功写入的 mtime 一致；
3. 使用该 preview 的 mtime 作为提交的并发令牌。

任一检查不通过（文件被用户或其他进程修改、删除、替换，或 adapter 无法提供
可靠的必要信息）即降级为普通 Apply / Reject 提案，绝不静默覆盖。

### 不能自动批准的情况

以下始终展示 Apply / Reject：

- 当前工作目录和 `/tmp` 以外的所有路径；
- 已存在但不在当前会话信任清单中的文件；
- 路径、mtime 或 adapter 状态无法验证的请求；
- Auto 模式关闭，或文件写入功能关闭。

信任按**精确文件路径**，不因批准一个文件而信任整个目录，也不因同名路径被
删除后重建而自动重新取得信任。

### 生命周期与界面

信任清单仅存在于当前打开的 Agent 会话内：`/clear`、New、会话释放/关闭和应用
重启都会清空。恢复聊天记录不会恢复文件自动写入权限。

自动提交仍生成聊天卡片，显示 `AUTO-CREATED` 或 `AUTO-UPDATED`、解析后的路径、
字节数，以及自动批准理由（新文件、此前创建、或用户已 Apply）。卡片不显示
Apply / Reject 按钮。所有降级情形继续使用现有人工审批卡片。

## 备选方案

Claude Code 的 `acceptEdits` 以整个工作目录为自动编辑范围。这里不采用该方案：
它减少提示次数，但会让 Agent 自动覆盖会话开始前就存在的用户文件。逐文件信任
能保留新建与迭代生成文件的流畅性，同时把原有文件的首次变更留给用户确认。

## 验收标准

1. Auto 模式在 cwd 或 `/tmp` 创建不存在的文件时不会暂停，并产生可审计结果卡。
2. Auto 模式不能直接覆盖会话开始前已有且未经 Apply 的文件。
3. 用户 Apply 成功后，当前会话内同一路径的后续修改可自动执行。
4. 外部修改、删除或 mtime 失配使后续写入回退到 Apply，且不会覆盖文件。
5. `/clear`、New、关闭或重启后，之前信任的文件再次修改必须 Apply。
6. 路径在 cwd 或 `/tmp` 外时始终需要 Apply。
